# Smart Text Classifier

## 1. Project Overview
A small machine-learning application that reads a short piece of text and classifies it into one of four categories: **Complaint, Inquiry, Feedback, Other**. It has a training script, a reusable prediction module, a Streamlit web interface and automated tests.

## 2. Objective
Built for an internship assignment: show a complete, understandable ML workflow (data → preprocessing → features → model → evaluation → application) using classical, explainable techniques.

## 3. Categories
| Category | Meaning | Example |
|---|---|---|
| Complaint | Reports a problem or dissatisfaction | "My internet is not working" |
| Inquiry | Asks a question or requests information | "How can I reset my password?" |
| Feedback | Opinions, praise or suggestions | "The service was excellent" |
| Other | Everyday text unrelated to the above | "I went to the market today" |

## 4. Technologies Used
Python 3, pandas (data), scikit-learn (TF-IDF, Logistic Regression, metrics, Pipeline), joblib (saving the model), Streamlit (interface), pytest/unittest (tests).

## 5. Machine Learning Approach
```
Dataset -> Preprocessing -> TF-IDF -> Logistic Regression -> Prediction
```
1. **Dataset** – labelled sentences in `data/dataset.csv`.
2. **Preprocessing** – lowercase, remove apostrophes and punctuation, collapse whitespace. Stop words are kept on purpose (words like "not" and "how" are strong clues).
3. **TF-IDF** – turns each sentence into numbers: words that are frequent in a sentence (TF) but rare across all sentences (IDF) get higher weights. Word pairs (bigrams) are included so "not working" is a feature.
4. **Logistic Regression** – learns which weighted words point to which category and outputs a probability for each of the four classes.
5. **Prediction** – the saved pipeline cleans raw text, vectorizes it, and returns the most probable category with its probability.

TF-IDF and Logistic Regression live in a single scikit-learn `Pipeline`, so TF-IDF is fitted on the training data only (no data leakage).

## 6. Dataset
The dataset was **written by me specifically for this internship project**. It is not taken from any external source.

Statistics generated by `python -m src.utils`:
- Total examples: **240** (after validation: 0 missing rows, 0 duplicates removed)
- Columns: `text`, `category`
- Class distribution: Complaint 60, Inquiry 60, Feedback 60, Other 60 (perfectly balanced)

It is small enough to create by hand yet large enough for a train/test split. Sentences vary in topic (orders, banking, travel, food, school, daily life) to avoid repetitive patterns.

## 11. Evaluation Results
Real output of `python -m src.train` (80/20 stratified split, `random_state=42`; 192 training / 48 test examples):

| Metric (test set) | Value |
|---|---|
| Accuracy | 0.7292 |
| F1-score (weighted) | 0.7293 |
| F1-score (macro) | 0.7293 |
| Precision (weighted) | 0.7429 |
| Recall (weighted) | 0.7292 |

Other numbers: training accuracy 1.0000; 5-fold cross-validation accuracy on the training part 0.6198 ± 0.0678.

| Class | Precision | Recall | F1 | Support |
|---|---|---|---|---|
| Complaint | 0.64 | 0.58 | 0.61 | 12 |
| Inquiry | 0.85 | 0.92 | 0.88 | 12 |
| Feedback | 0.60 | 0.75 | 0.67 | 12 |
| Other | 0.89 | 0.67 | 0.76 | 12 |

Confusion matrix (rows = true, columns = predicted; order Complaint, Inquiry, Feedback, Other):
```
Complaint: [7, 1, 4, 0]
Inquiry:   [1, 11, 0, 0]
Feedback:  [2, 0, 9, 1]
Other:     [1, 1, 2, 8]
```
**How to read this:** accuracy = share of correct predictions. Precision = when the model says a class, how often it is right. Recall = how many real examples of a class it finds. F1 balances precision and recall. Weighted F1 is used as the main F1 (averages per-class F1 by class size); here classes are balanced so macro and weighted are equal.

**Honest interpretation:** training accuracy is 100% but test accuracy is ~73% and cross-validation ~62%, so the model partly memorises the small training set. With only 48 test sentences, each mistake moves accuracy by about 2 points, so these numbers are rough estimates. Inquiry is easiest (question words); Complaint vs Feedback is the most confused pair, which is expected because both talk about products and services.

## 13. Limitations
- **Small dataset (240 sentences):** results are noisy; the large gap between training accuracy (100%) and test/cross-validation accuracy shows overfitting.
- **Hand-written data:** one author's wording; real customers write differently (slang, typos, longer messages).
- **Bag-of-words:** TF-IDF ignores meaning and word order beyond word pairs, so sentiment without typical keywords ("lovely") can mislead it.
- **Overlap between classes:** a sentence can be both a complaint and a question ("Why is my order late?"); only one label is allowed.
- **No "unknown" option:** the model always picks one of four classes, even for gibberish or other languages (English only).
- **Confidence is not accuracy:** the probabilities are estimates and can be too high or too low.

## 14. Future Improvements
- Collect a larger, real-world labelled dataset (thousands of examples) and re-evaluate.
- Compare other classical models (Linear SVM, Naive Bayes) with cross-validation and tune on a validation set.
- Add a "low confidence → please rephrase" threshold in the UI.
- Add typo robustness (character n-grams) and multilingual support.
